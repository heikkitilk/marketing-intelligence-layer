## B1. The gate cannot pass, whatever the extractor produces

`evaluate_quality_pilot` divides the transferability and novelty numerators by
`expected_learning`, the count of packets the blind reviewer labeled `learning`
(`src/marketing_intelligence/quality.py:1201`, `:1243-1246`). It increments those
numerators only for packets whose own label carries the matching flag
(`:1210-1220`).

[DATA] Of the 24 immutable labels, 5 are `learning`. Of those 5, exactly 1 has
`requires_transferability: true` and exactly 2 have `baseline_novel: true`.

Therefore, before any model call:

| Metric | Max achievable | Threshold | Result |
| --- | --- | --- | --- |
| `transferability` | 1/5 = 0.20 | 0.70 | fails |
| `novelty_non_harness_usefulness` | 2/5 = 0.40 | 1.00 | fails |

A perfect extractor scores `reduced_scope`. Running the 23 Claude extractions
would spend roughly 84 minutes and 530,000 input tokens to reach a verdict that
is already determined.

[LOGIC] This is a denominator defect, not a threshold that is set too high. The
numerators are conditioned on a per-label requirement flag while the denominator
counts every learning packet, so an honest reviewer who marks most learnings
non-transferable forces the pipeline to fail. The consistent denominators are
the count of labels that carry each flag: 1 for transferability, 2 for novelty.
`relevance` has the same shape but is currently harmless, because all 5
learning labels carry `requires_relevance: true`.
